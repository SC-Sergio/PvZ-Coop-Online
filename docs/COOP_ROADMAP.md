Do not skip ahead to decorative features while P0–P6 are unstable. Online Playable V1 is complete only when every definition-of-done item in the project request has reproducible evidence, including a full match across different networks.

## Backend investigation

Evaluate Epic Online Services and maintained alternatives against current SDK availability, licensing, supported desktop platforms, lobby/invite APIs, NAT traversal/relay, identity, reconnect, operational constraints, and long-term maintainability. Keep gameplay behind interfaces and record source links and an explicit decision before provider integration.

Official-source review (2026-10-06): EOS advertises PC support and service availability, and has lobby and P2P relay support. However, its current developer agreement restricts combining the SDK with code under a license that would require the SDK to be governed by different terms. Compatibility with this project's LGPL-3.0-or-later distribution is unresolved, so EOS is not selected without legal review or written clarification ([Epic developer agreement](https://onlineservices.epicgames.com/services/terms/agreements), [EOS PC support](https://dev.epicgames.com/docs/epic-online-services/eos-get-started/eos-get-started-reference), [EOS relay control](https://dev.epicgames.com/docs/en-US/api-ref/enums/eos-e-relay-control)). Steam Datagram Relay does provide authenticated, encrypted relaying but Valve says the open-source SteamNetworkingSockets build cannot access the relay network; use across storefronts requires separate SDKs/conditions and a Steam release ([Steam Datagram Relay docs](https://partner.steamgames.com/doc/features/multiplayer/steamdatagramrelay?l=english&language=english)).

Selected technical direction: `libdatachannel` implements WebRTC DataChannels across Windows/macOS/Linux and v0.24.3 is MPL-2.0; the optional vcpkg feature pins the resolved manifest dependency and the local Debug build succeeds ([official repository/license](https://github.com/paullouisageneau/libdatachannel), [project overview](https://libdatachannel.org/)). WebRTC supports direct ICE paths and TURN relay fallback; TURN can be self-hosted with coturn, which is actively maintained, but still needs a public server, DNS/certificate, bandwidth, and secure short-lived credentials ([coturn](https://github.com/coturn/coturn)). The C++ signaling client, Node room service, and lobby UI are implemented and tested together on localhost. No public relay/signaling deployment or credentials are available in this workspace, so cross-network Internet reachability is not yet verified. TCP stays limited to trusted LAN testing.
